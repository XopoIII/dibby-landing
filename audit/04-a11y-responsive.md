# Аудит доступности (a11y / WCAG) и адаптивности — лендинг dibby

Дата: 2026-06-14
Проверено: `landing/index.html`, `landing/styles.css`, `landing/i18n.js`, `build.cjs`, сборка `dist/en/` (= `dist/index.html`) и `dist/ar/` (RTL).
Код **не менялся** — это только отчёт.

## Общая оценка

Лендинг уже заметно проработан по доступности: есть `:focus-visible`-стили (с комментарием «было полностью отсутствует»), осознанно подобранные AA-контрастные переменные (`--ink-soft #566068`, `--peach-text #9c5f20` с комментариями про WCAG AA), семантические `header/nav/main/footer`, `aria-label` на навигациях, `aria-expanded`/`aria-controls` на FAQ-аккордеоне, поддержка `prefers-reduced-motion`, корректный RTL для арабского (`dir="rtl"` в `<html>`, зеркалирование текста). Ниже — оставшиеся проблемы, отсортированы по важности.

Легенда серьёзности: 🔴 высокая · 🟠 средняя · 🟡 низкая.

## A. Доступность (WCAG)

### A1. 🔴 Языковой переключатель и текущий язык невидимы/неверны без JS
- **Элемент/селектор:** `#langMenu` (`role="menu"`), `#langCurrent`, кнопка `#langBtn`.
- **Проблема:** меню языков строится только в JS (`buildLangMenu()`), в `dist/*/index.html` оно запечено пустым (`<div id="langMenu" role="menu"></div>`). При выключенном JS переключение языка недоступно. Хуже: `#langCurrent` в каждой локали запечён как текст `English` (в `dist/ar/index.html` тоже `English`), хотя страница арабская — до выполнения JS пользователь/скринридер видит неверную метку. Также `role="menu"` на пустом контейнере — это меню без пунктов (нарушение ARIA: роль `menu` подразумевает `menuitem`-потомков).
- **Фикс:** запекать пункты меню в `build.cjs` (как уже делается с FAQ/stores) или хотя бы выводить ссылки `<a href="/ar/">…` на каждую локаль (тогда работает без JS, и URL == контент). `#langCurrent` запекать реальным именем локали (`meta.name`). Пустую роль `menu` не оставлять — либо наполнять пунктами, либо снять роль.

### A2. 🟠 У кнопки языка нет доступного имени (aria-label) и нет `id`-связи с меню
- **Элемент/селектор:** `#langBtn` (`<button class="lang__btn" aria-haspopup="true" aria-expanded="false">`).
- **Проблема:** доступное имя складывается только из текста `#langCurrent` («English»), без поясняющего «Язык/Language». В `i18n.js` уже есть ключ `langLabel` («Язык»/«Language»), но он нигде не применяется. `aria-haspopup="true"` корректнее задать `aria-haspopup="menu"`. Нет `aria-controls="langMenu"`.
- **Фикс:** добавить `aria-label`/видимую подпись из `langLabel`, `aria-haspopup="menu"`, `aria-controls="langMenu"`.

### A3. 🟠 Меню языка не управляется с клавиатуры (нет Esc / стрелок / возврата фокуса)
- **Элемент/селектор:** `#lang`, обработчики в `buildLangMenu()`.
- **Проблема:** открытие — по `click`, закрытие — по `document click`. Нет закрытия по `Escape`, нет навигации стрелками по `role="menu"`, после закрытия фокус не возвращается на кнопку. Для виджета с `role="menu"` это нарушение паттерна WAI-ARIA. Сами пункты — `<button>`, так что Tab-доступность есть, но это не «меню».
- **Фикс:** добавить обработку `Escape` (закрыть + вернуть фокус на `#langBtn`); либо упростить роль до обычного списка ссылок/кнопок (см. A1) и убрать `role="menu"`, чтобы не обещать неподдерживаемый паттерн.

### A4. 🟠 Лейбл cookie-баннера не локализован
- **Элемент/селектор:** `#cookieBanner` → `aria-label="Cookie consent"`, `role="dialog"`.
- **Проблема:** в `dist/ar/index.html` (и во всех локалях) `aria-label` остаётся английским «Cookie consent», тогда как страница арабская/немецкая и т. д. Скринридер на арабской странице озвучит английскую метку. `role="dialog"` без управления фокусом тоже спорный — баннер не модальный (это скорее `region`).
- **Фикс:** локализовать `aria-label` через i18n (например, переиспользовать ключ из cookie-секции), либо заменить `role="dialog"` на `role="region"` с локализованным `aria-label`. Текст внутри (`data-i18n="cookieText"`) уже локализуется — нужно покрыть и атрибут.

### A5. 🟡 Декоративный SVG-логотип-ссылка `dibby` — текст внутри стилизуется обводкой; в hero логотип — `<div>`
- **Элемент/селектор:** `a.logo[href="#top"]` (есть `aria-label="dibby"` ✔), но `div.logo` в hero (`<div class="logo">dibby</div>`) и в футере.
- **Проблема:** логотип в `header` — корректная ссылка с `aria-label`. Но в hero и footer это `<div>`/просто текст «dibby», задублированный визуально. Поскольку это тот же бренд-вордмарк, для скринридера он читается трижды («dibby … dibby … dibby»). Не критично, но шумно. Логотип использует `-webkit-text-stroke` — на старых браузерах без поддержки текст всё равно остаётся реальным (ок).
- **Фикс:** при желании пометить декоративные повторы как `aria-hidden="true"` либо оставить (текст всё-таки реальный и читаемый).

### A6. 🟡 Социальные ссылки в футере — `href="#"` (пустые), скрываются JS
- **Элемент/селектор:** `.socials a[data-social]` (3 шт., `href="#"`).
- **Проблема:** в запечённом HTML это «битые» якоря `href="#"`; видимы и кликабельны, пока JS их не спрячет (`display:none` при отсутствии URL). Без JS — три ссылки в никуда (ведут наверх страницы). `aria-label` у них есть (Discord/YouTube/X) ✔.
- **Фикс:** запекать соц-ссылки скрытыми по умолчанию (или не рендерить, пока нет URL) — чтобы не зависеть от JS. Сейчас канал не настроен, так что в no-JS они вводят в заблуждение.

### A7. 🟡 Контраст: мелкий текст бейджей сторов и `.live-tag`
- **Элемент/селектор:** `.store__small` (`font-size:0.62rem; opacity:0.85`) — `--cream #fffdf7` поверх `--ink #3d4a52`.
- **Проблема:** базовый контраст cream-на-ink ≈ 9–10:1 (отлично), но `opacity:0.85` снижает эффективный контраст и шрифт очень мелкий (≈10px). По WCAG ещё проходит, но на грани комфортной читаемости. `.live-tag` (0.66rem, ink на полупрозрачном cream) — декоративная плашка «gameplay», не критичный контент.
- **Фикс:** убрать `opacity` у `.store__small` (контраст и так с запасом, прозрачность только вредит) либо поднять размер. Низкий приоритет.

### A8. 🟡 `eyebrow` (надзаголовки) дублируют навигацию как текст
- **Элемент/селектор:** `.eyebrow[data-i18n="navHow"]`, `navFriends`, `navWhy`, `navFaq`.
- **Проблема:** не a11y-баг, но семантически надзаголовки секций используют те же ключи, что и пункты меню — для скринридера это нормально (просто текст). Заголовки секций — корректные `<h2>`. Иерархия заголовков: `h1` (hero) → `h2` (секции) → `h3` (карточки) — **корректна, без пропусков** ✔.

### A9. ✅ Что сделано хорошо (для протокола)
- `:focus-visible` со светлым кольцом на тёмном футере/бейджах сторов (`outline-color: var(--cream)`), `:focus:not(:focus-visible)` гасит кольцо для мыши — корректно.
- FAQ-аккордеон: `<button>` с `aria-expanded`/`aria-controls`, ответ `role="region"` + `aria-labelledby` — образцово.
- `<table class="keyfacts">` с `<th scope="row">` — правильная разметка таблицы.
- `lang`-атрибут на `<html>` корректен в каждой локали (`dist/ar` → `lang="ar"`, `hreflang` zh-Hans/zh-Hant и т. д.).
- Картинки: значимые имеют осмысленный `alt` (скриншоты, hero-геймплей); декоративные (`step__art`, confetti-маскоты, силуэты заблокированных друзей) — `alt=""` ✔. Раскрытые друзья получают имя в `alt`, заблокированные — `alt=""` ✔.
- `prefers-reduced-motion` уважается во всех анимациях (bob, livePulse, hintPulse, friendPop, smooth-scroll).
- Форм на странице **нет** (e-mail-сбор не реализован — все CTA это ссылки-якоря/в сторы), поэтому проблем label/ошибок валидации нет.

## B. RTL (арабский)

### B1. ✅ База RTL корректна
- `dist/ar/index.html`: `<html lang="ar" data-script="arab" dir="rtl">` ✔. CSS зеркалит `direction`, выравнивание hero/keyfacts/store-текста по правому краю (`[dir="rtl"] …`).

### B2. 🟠 Логотип/`hero-h1` содержат латиницу и принудительный перенос — в RTL может ломаться порядок
- **Элемент/селектор:** `.hero-h1` (`white-space: pre-line`, текст с `\n`), бренд «dibby» (латиница) внутри RTL-потока.
- **Проблема:** в арабском запечён двухстрочный `h1` через перевод строки (`pre-line`). С `text-align:right` всё ок, но смешение латинского «dibby» (в логотипе, в og) с арабским может давать спорный bidi-порядок пунктуации возле латинских вставок (например «— dibby» в title). Визуально на лендинге это в основном изолированный вордмарк, риск низкий, но стоит проверить вживую.
- **Фикс:** проверить рендер в реальном RTL-браузере; при необходимости оборачивать латинские вставки в `<bdi>` или `dir="ltr"`-спан. Сейчас критичных поломок в разметке не видно.

### B3. 🟡 Мелкие лево-привязанные элементы не зеркалятся
- **Элемент/селектор:** `.store__txt { text-align:left }` зеркалится (`[dir=rtl]` правит), но, например, `.live-tag { left:12px; bottom:12px }`, `.demo-hud { left:12px }`, `.faq-q { text-align:left }`, `.lang__opt { text-align:left }`, `.keyfacts th/td` (зеркалится ✔).
- **Проблема:** `.faq-q` и `.lang__opt` имеют жёсткий `text-align:left` без RTL-переопределения → в арабском вопросы FAQ и пункты меню языков прижмутся влево вместо права. `.live-tag`/`.demo-hud` позиционированы абсолютно слева — в RTL логичнее справа (но это декоративные плашки на телефоне, не текст).
- **Фикс:** заменить `text-align:left` на `text-align:start` (или добавить `[dir="rtl"]`-правила) для `.faq-q`, `.lang__opt`, `.store__txt`, `.footer-col`. Для абсолютно-позиционированных плашек использовать логические свойства (`inset-inline-start`) если важно зеркалить.

## C. Адаптивность

### C1. 🟠 Бейджи сторов могут давать горизонтальный скролл на 320px
- **Элемент/селектор:** `.store { min-width: 184px }`; на ≤560px → `min-width:0; flex:1 1 100%`.
- **Проблема:** на узких экранах правило `@media (max-width:560px)` снимает `min-width` и растягивает бейдж на всю ширину — это хорошо. Но `.store__big` (например `«VK Mini Games»`, «Yandex Games») + glyph + паддинги при очень длинных локализованных строках (de/ru) могут не помещаться в одну строку и переполнять. Текст не переносится (`store__txt` колонка, но `store__big` одной строкой). `body { overflow-x: hidden }` маскирует горизонтальный скролл глобально, но контент может обрезаться.
- **Фикс:** проверить на 320px с ru/de; при необходимости разрешить перенос/уменьшить шрифт `.store__big` на узких экранах. `overflow-x:hidden` на body — костыль, который скрывает реальные переполнения (см. C4).

### C2. 🟠 Длинные слова в de/ru/uk/fi-подобных локалях — нет `overflow-wrap`/`hyphens`
- **Элемент/селектор:** `.hero-h1`, `.section-title`, `.btn`, `.store__big`, `.eyebrow`.
- **Проблема:** заголовки используют `text-wrap: balance/pretty`, но нигде нет `overflow-wrap: break-word` / `hyphens: auto`. Немецкие составные слова (например «Release-Tag», «Magnetseil», в навигации «Warum es packt») и длинные кнопки (`friendsCta` в de: «Rette die anderen 30. Wir sagen dir Bescheid, sobald es losgeht.») на 320px могут вылезать за контейнер кнопки/карточки. `body{overflow-x:hidden}` прячет это, но визуально текст может обрезаться кнопкой.
- **Фикс:** добавить `overflow-wrap:break-word` (и `hyphens:auto` для подходящих locale) на заголовки и текст кнопок/бейджей.

### C3. 🟡 Тап-таргеты: навигация в шапке и пункты языка — высота < 44px
- **Элемент/селектор:** `.nav a { padding: 4px 2px }` (но `.nav` скрыта на ≤880px — значит на мобильном неактуально ✔); `.lang__opt { padding: 9px 12px }` (≈ 36–38px высотой); `.footer-col a { padding: 4px 0 }` (≈ 28px); `.footer-legal a`, `.socials a { 40×40px }`.
- **Проблема:** основные мобильные CTA крупные (`.btn--lg`, `.mobile-cta .btn` во всю ширину) — отлично, ≥44px ✔. Но **ссылки в футере** (`.footer-col a`, `.footer-legal a`) имеют вертикальный паддинг всего 4px → тап-высота ~28px, ниже рекомендованных 44px (WCAG 2.5.5 / 2.5.8 минимум 24px они проходят, но не «комфортные» 44). Пункты языка `.lang__opt` ~38px и кнопка `.lang__btn` (`padding:7px 12px` ≈ 34px) — тоже чуть ниже 44px. Соц-иконки 40×40 — почти ок.
- **Фикс:** поднять вертикальный паддинг ссылок футера и `.lang__opt`/`.lang__btn` до ~44px тап-зоны (можно через `min-height` + `display:flex`), особенно на мобильном.

### C4. 🟡 `overflow-x: hidden` на body маскирует переполнения
- **Элемент/селектор:** `body { overflow-x: hidden }`.
- **Проблема:** скрывает горизонтальный скролл глобально — удобно, но прячет реальные переполнения (C1/C2). Если что-то вылезает, пользователь просто теряет часть контента без возможности доскроллить.
- **Фикс:** оставить как защиту, но устранить первопричины (wrap/hyphens, гибкие бейджи), а не полагаться на скрытие.

### C5. ✅ Что сделано хорошо
- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` — корректный, с `viewport-fit=cover` и `env(safe-area-inset-bottom)` в `.mobile-cta`/cookie-баннере (учёт «чёлки») ✔.
- Контейнер ограничен `--maxw: 1180px`, паддинги через `clamp()` — хорошо для широких экранов и планшетов.
- Брейкпоинты `880px` (сетки → 1 колонка, nav скрыт, появляется sticky mobile-CTA) и `560px` (бейджи во всю ширину, меню языка в 1 колонку, сетка друзей мельче) — логичны.
- Sticky mobile-CTA не накладывается на cookie-баннер (`.consent-open .mobile-cta { display:none }`) ✔.
- `body { padding-bottom: 72px }` на мобильном освобождает место под sticky-CTA ✔.
