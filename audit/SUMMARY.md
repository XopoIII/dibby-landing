# Сводный аудит лендинга Dibby — SUMMARY

Дата: 2026-06-14. Аудиторы: 6 саб-агентов (карта + SEO + перфоманс + Worker + a11y + UX + мелочи).
Код не менялся — только анализ. Детали в `audit/00-map.md` … `audit/06-misc.md`.

## Контекст
Чистый статический лендинг (без фреймворка): исходник в `landing/` → `build.cjs` запекает HTML по
**19 локалям** в `dist/`. Edge-воркер `worker.js` поверх Cloudflare Workers Assets делает только
302-редирект с `/` по языку, остальное — passthrough. Деплой **ручной** (`wrangler deploy`), без CI,
`dist/` не в гите. Продукт **уже частично релизнут** (RuStore + Telegram Mini App живые), но лендинг
по-прежнему написан как pre-launch «notify me» — это корень большинства проблем.

## 🔴 БЛОКЕРЫ (чинить первыми — ломают конверсию и вводят в заблуждение)

| # | Находка | Источник | Суть |
|---|---------|----------|------|
| B1 | **Первичный CTA ведёт в никуда** | UX | `CTA_URL = preregAndroid \|\| preregIos \|\| discord \|\| ""` — все пусты → каждая кнопка «Напомнить» падает на `href="#get"` и просто скроллит. Самый крупный повторяющийся элемент страницы не делает ничего, хотя сторы живые. |
| B2 | **«Скоро / Coming soon» поверх живого продукта** | UX, SEO | Остатки pre-launch по всему сайту: статус-строка, `factStatusV`, `footerSoon`, ribbon-ы, hero, **meta/OG/Twitter**, JSON-LD `availability: PreOrder`. Для релизнутого продукта это и ложь пользователю, и SEO-вред (должно быть `InStock`). |
| B3 | **Ссылки на сторы не существуют для краулеров и при сбое JS** | SEO, UX, a11y | В запечённом HTML все store-бейджи и футер-ссылки — `href="#get"`; реальные URL (rustore.ru, t.me/dibbyplay_bot) подставляет только клиентский JS. Краулеры без JS не видят исходящих ссылок на живые листинги; без JS кнопки мертвы. |
| B4 | **Форма захвата заявок отсутствует** | UX | Текст обещает «оставь заявку — придёт письмо в день выхода», но во всём `index.html` нет ни `<form>`, ни `<input>`, ни `mailto`. Либо собирать заявки нечем, либо (раз продукт живой) сменить парадигму на «Играть сейчас». |

> Все четыре — одна корневая причина: **лендинг не переведён из режима «pre-launch» в «released»**.
> Это первый и главный проход правок.

## 🟠 HIGH (заметный ущерб SEO / безопасности / производительности)

| # | Находка | Источник | Фикс кратко |
|---|---------|----------|-------------|
| H1 | **Нет ни одного security-заголовка** (HSTS, CSP, X-Content-Type-Options, Referrer-Policy, Permissions-Policy) | Worker | Обёртка `harden()` над `env.ASSETS.fetch` или `dist/_headers`. Сниппеты в 03. |
| H2 | **Нет управления Cache-Control** — Workers Assets отдаёт дефолты; HTML не `no-cache`, ассеты без `immutable` | Worker, Perf | `dist/_headers`: HTML коротко, `/assets/*` долго+immutable. Связать с хешированием имён. |

## Что в порядке (подтверждено)
- **Секретов в коде нет** — `account.id` только в `.wrangler/cache/`, корректно в `.gitignore`.
- **Аналитика чистая** — ни Я.Метрики, ни GA, ни битых счётчиков (только закомментированные hook-точки).
- **OG-превью** — `assets/og.png` ровно 1200×630, абсолютный https-URL, полный набор мета, локализуется.
- **Нет mixed content**, нет битых внутренних ссылок/orphan, meta-keywords отсутствуют (правильно).
- **hreflang** — 19 локалей + x-default, коды консистентны; один h1 на страницу; canonical самоссылающийся.
- **a11y-база сильная** — `:focus-visible`, AA-контраст переменными, семантика, RTL `dir="rtl"` для `ar`, FAQ-аккордеон с `aria-expanded`, `prefers-reduced-motion`.
- **Perf-база сильная** — self-host woff2 с preload и `font-display:swap`, LCP-webp с `fetchpriority="high"`, `width/height` у `<img>`, `aspect-ratio`, lazy below-the-fold.
- **Воркеры крошечные** (~3.8 + 1.7 КБ), холодный старт не проблема; 302 на `/` корректен (`no-store` + `Vary`).

## Рекомендованный порядок правок (по одной теме за проход)
1. **Проход «released»** (B1–B4): развести живые/не-живые локали, убрать «Скоро», запечь реальные store-URL в HTML, починить/перенаправить CTA, решить судьбу формы заявок.
2. **Worker hardening** (H1, H2, M5, M6): security-заголовки + `_headers` + Cache-Control + 404 + канонизация хоста.
3. **SEO-сущность** (H3, M3, M4, L4): `sameAs`, `availability: InStock`, мета для legal, верификация Вебмастера.
4. **Perf** (H4, H6, M1, M2, L3, L8): CLS-резервирование, per-locale i18n + defer, критический CSS, пережатие картинок.
5. **a11y-добивка** (H5, M7, M8, M9, L5): меню языка без JS, локализация aria, RTL-зеркалирование, тап-таргеты.
6. **Мелочи** (L1, L2, L7, L9): favicon/manifest, чистка редиректов dib.by, синхронизация доков.
